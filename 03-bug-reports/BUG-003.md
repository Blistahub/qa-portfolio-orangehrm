# BUG-003 — El buscador etiqueta como «Invalid» un nombre correcto si no se elige una sugerencia

| | |
| --- | --- |
| **Severidad** | Media |
| **Prioridad** | Alta |
| **Estado** | Abierto |
| **Módulo** | PIM > Employee List |
| **Requisito relacionado** | [RF-11](../00-requisitos.md#2-listado-y-búsqueda-de-empleados-pim--employee-list) |
| **Caso de prueba** | [CP-015](../02-casos-de-prueba.md#cp-015) |
| **Entorno** | Chrome (estable) · Windows 11 Pro 24H2 · `opensource-demo.orangehrmlive.com` (OrangeHRM OS 5.x) |
| **Reportado por** | David Coya Moreno |

## Precondiciones

Sesión iniciada con el usuario `Admin`. Existe al menos un empleado cuyo nombre empieza por `Luc`.

## Pasos para reproducir

1. Ir a **PIM > Employee List**.
2. Escribir `Luc` en el campo *Employee Name*.
3. Esperar a que se despliegue la lista de sugerencias, **sin pulsar ninguna**.
4. Pulsar directamente **Search**.

## Resultado esperado

Una de estas dos conductas, ambas aceptables:

- El sistema busca por coincidencia parcial y devuelve los empleados cuyo nombre contiene `Luc`; o
- el sistema indica con un mensaje comprensible que debe seleccionarse una de las sugerencias
  ofrecidas.

## Resultado obtenido

Aparece el mensaje **«Invalid»** bajo el campo y no se ejecuta ninguna búsqueda. El texto es
correcto —de hecho ha generado sugerencias válidas justo antes—, pero el sistema lo declara
inválido.

El mensaje es además engañoso: no describe el problema real, que no es que el dato sea incorrecto,
sino que el campo exige un empleado seleccionado de la lista y no texto libre.

## Notas técnicas

El campo no envía texto: envía un identificador. En las DevTools se observa que al seleccionar una
sugerencia el buscador emite

```
GET /web/index.php/api/v2/pim/employees?…&empNumber=7
```

Es decir, el control es en realidad un **selector de entidad** disfrazado de campo de texto. Cuando
no hay sugerencia elegida no existe `empNumber` que enviar, y la validación del cliente marca el
campo como inválido **sin llegar a lanzar petición alguna** (no se registra ninguna llamada en la
pestaña *Network*).

Merece la pena señalar que el endpoint de sugerencias sí acepta texto parcial: la búsqueda por
coincidencia ya existe en el servidor y es la que alimenta el desplegable. La limitación es
exclusivamente del control de la interfaz.

## Análisis de impacto

Severidad **Media** —no hay pérdida de datos y existe un camino alternativo— pero prioridad
**Alta**, y la diferencia es deliberada:

- La búsqueda de empleados es la operación más frecuente del módulo; el coste se multiplica por su
  frecuencia de uso.
- El usuario no dispone de información para corregirse: el mensaje afirma que su dato está mal
  cuando está bien.
- Es el patrón de incidencia que llega a soporte como *«el buscador no funciona»*, difícil de
  diagnosticar porque, técnicamente, funciona.

## Recomendación

Por orden de preferencia:

1. Permitir la búsqueda por texto parcial reutilizando el endpoint que ya alimenta el
   autocompletado. Es la conducta que el usuario espera y la capacidad ya existe en el servidor.
2. Si se mantiene la restricción por diseño, sustituir *«Invalid»* por un mensaje que describa la
   acción requerida —*«Seleccione un empleado de la lista de sugerencias»*— y marcar visualmente el
   campo como selector, no como texto libre.
